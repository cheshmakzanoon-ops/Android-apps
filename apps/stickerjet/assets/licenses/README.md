# StickerJet test media and fixtures: provenance

Every file in `assets/source/` and `core/src/test/resources/webp/` was generated in this repository.
None is a photograph or footage of a real person, and none comes from a third party, so no licence
beyond the project licence applies.

## Source clips (`assets/source/`)

| File | Content | Size | SHA-256 |
|---|---|---|---|
| `moving_subject_320x240_3s.mp4` | 3 s, 24 fps, 320x240, H.264. Orange disc (radius 36 px) on a navy background, moving on a sine path. | 7420 B | `25ed8d81ad25dc9311ef2973459f3d653771e93445a087b7e1c532eaeeaf1fb4` |
| `rotated_90_320x240_3s.mp4` | The same content with display matrix rotation -90 (ffprobe), which is 90 degrees clockwise. Displayed size is 240x320. | 7420 B | `2bf73d5ad22a29b89b95f34055f8980d72b17310360c7a4993f1bb4bf8e489ae` |

Generator: `apps/stickerjet/tools/make_test_media.sh` (ffmpeg 6.1.1, libx264). The commands it runs are:

```sh
# Synthetic frames from ffmpeg's colour source and a per-pixel equation (no input files)
ffmpeg -f lavfi -i "color=c=0x1d3557:s=320x240:r=24:d=3,format=rgb24,geq=r=...:g=...:b=...,format=yuv420p" \
  -c:v libx264 -preset slow -crf 30 -pix_fmt yuv420p -movflags +faststart -an moving_subject_320x240_3s.mp4

# Rotated copy: encode upright, then remux with a display matrix of -90 (clockwise 90)
ffmpeg -display_rotation:v:0 -90 -i upright.mp4 -c copy -movflags +faststart rotated_90_320x240_3s.mp4
```

The `rotate=90` metadata tag was tried first and does not write a display matrix with ffmpeg 6.1.1,
so it is not used.

## Journey clip (`journey-clip.mp4`): synthetic, contains NO person

- File: `assets/source/journey-clip.mp4`. It is a byte-identical copy of `moving_subject_320x240_3s.mp4`
  (SHA-256 `25ed8d81ad25dc9311ef2973459f3d653771e93445a087b7e1c532eaeeaf1fb4`), made with `cp`, not re-encoded.
- Content: SYNTHETIC. An orange disc moves on a navy background. It contains NO person and no photograph or
  footage of anyone.
- `build.gradle.kts` maps `assets/source` into the androidTest assets, so the instrumented journey reads the
  clip by its asset name `journey-clip.mp4`.
- Consequence: the journey exercises only the NO-SUBJECT FALLBACK. The segmenter finds no person here, so the
  masked path is not exercised. Segmentation quality is NOT validated by this clip. No legally usable clip with a
  real person was available in this work, and public media hosts are blocked by the egress policy. Validating
  segmentation needs a licensed clip with a person, checked by CI or on a device.

## ML Kit selfie segmentation (third-party component)

- **Library:** `com.google.mlkit:segmentation-selfie`, version `16.0.0-beta6`. The version is taken from
  `gradle/libs.versions.toml` (key `mlkitSelfie`). It is a beta release.
- **Provider and licence:** Google ML Kit. This is third-party code that this project does not own. Its
  licence text is not reproduced here, and none has been paraphrased. The repository contains no ML Kit
  source or model file.
- **Cross-reference:** the public `googlesamples/mlkit` vision quickstart declares the same coordinate and
  version in `android/vision-quickstart/app/build.gradle`. That confirms the coordinate and version only. The
  sample's Apache-2.0 licence covers the sample code, not the library, and no code was copied from it.
- **Bundled model (ADR-002 claim, NOT CONFIRMED here):** `docs/decisions.md` ADR-002 states that the model is
  bundled, runs on device and needs no network. This environment cannot download the AAR (Google Maven
  returns 403), so the bundling, the model file name and its size are not verified. Confirm them from the
  AAR's contents before release.
- **Upstream terms URL: NOT CONFIRMED.** developers.google.com is blocked from this environment, and the
  sample README links to no terms document. The PM should add the ML Kit terms URL from the official page
  once it can be read. No URL has been guessed.
- **Licence wording: NOT REVIEWED BY COUNSEL.** `docs/design.md` already records that the ML Kit licence
  wording in Settings needs legal review before Play submission. Until that review, treat any licence
  statement in the app as a placeholder.
- **Scope:** segmentation is person-focused. Pets and objects are not segmented (see ADR-002).
